# Tutoriel guidé Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Une visite guidée en bulles (driver.js) au premier lancement et après la mise à jour qui l'apporte, passable, relançable depuis la barre latérale.

**Architecture:** Python décide *si* la visite démarre (`utils/tutoriel.py`, fichier « tutoriel vu » dans le dossier de config) et fournit les étapes en JSON ; un script injecté par `st.html` pilote driver.js dans la page, change de page en cliquant les boutons du menu et attend l'élément visé. La fin (Terminer ou Passer) est signalée à Python par un clic JS sur un bouton Streamlit caché qui écrit le marqueur.

**Tech Stack:** Streamlit 1.58, driver.js 1.3.x (IIFE, MIT) servi en statique, pytest + AppTest, Playwright pour la vérification visuelle.

**Spec:** `docs/superpowers/specs/2026-10-20-tutoriel-design.md`

## Global Constraints

- Textes des 15 bulles : copiés **mot pour mot** de la spec (section « Les étapes »), vouvoiement.
- Aucun `<` suivi d'une lettre ou d'un chiffre dans un texte de `<script>` passé à `st.html` (DOMPurify le supprime sans erreur) ; driver.js est chargé par `<script src="app/static/…">`.
- Pendant la visite, aucun clic ne lance de recherche, d'invitation, de message ni de veille : le script ne clique **que** des boutons du menu (`.st-key-nav_---…`), des onglets (`[data-baseweb="tab"]`) et le bouton caché de fin.
- Élément visé introuvable après 4 s → bulle au centre (étape sans `element`), la visite continue.
- Couleurs et police de `DESIGN.md` : bulle blanche, bouton principal `#172982`, texte Inter ; `prefers-reduced-motion` respecté (driver `animate:false`).
- Marqueur « tutoriel vu » : `<config_dir>/tutoriel_vu.txt`, par personne ; jamais supprimé par une mise à jour.

## Review Focus

- Un rerun Streamlit (tout clic) ne doit pas relancer la visite depuis l'étape 0 → garde `window.__wrTour` avec un identifiant de lancement (test AppTest : même identifiant entre deux reruns).
- La visite affichée, la fenêtre « Nouveautés » ne doit pas s'ouvrir aussi → test AppTest Task 3.
- Une fois « tutoriel vu » écrit, aucun script de visite n'est injecté au lancement suivant → test AppTest Task 3.
- « Revoir le tutoriel » relance même si le marqueur existe, et avec un nouvel identifiant → test AppTest Task 3.
- Sur un écran étroit, la barre latérale repliée : les étapes qui la visent tombent au centre plutôt que de pointer dans le vide → vérification Playwright Task 4 en 390 px.

### Task 2: driver.js en statique et script de visite

**Files:**
- Create: `static/driver.js.iife.js`, `static/driver.css` (driver.js 1.3.1, depuis `https://cdn.jsdelivr.net/npm/driver.js@1.3.1/dist/` ; ajouter `static/LICENSE-driver.js.txt`)
- Create: `ui/tutoriel.py`
- Modify: `.streamlit/config.toml` (`[server] enableStaticServing = true`)
- Test: `tests/test_tutoriel_script.py`

**Interfaces:**
- Consumes: `etapes_pour` (Task 1).
- Produces: `script_visite(etapes: list[dict], identifiant: str) -> str` (HTML : `<link>` vers `app/static/driver.css`, `<script src="app/static/driver.js.iife.js">`, puis un `<script>` de pilotage) ; `CLE_FIN = "tutoriel_fini"`.

Comportement du script de pilotage (algorithme à écrire tel quel, sans `<`) :
1. Si `window.__wrTour` existe avec le même `identifiant` → ne rien faire (rerun). Sinon le remplacer.
2. Attendre que `window.driver` soit chargé (sondage 100 ms, 5 s max ; sinon abandonner silencieusement : l'outil reste utilisable).
3. Pour l'étape i : si `page` ≠ page active (bouton menu `[kind="primary"]` dans `.st-key-nav_menu`), cliquer `.st-key-nav_---<suffixe> button` (suffixe = la clé interne telle que Streamlit l'assainit : réutiliser le même mapping que les tests, ex. `Dashboard`, `Recherche`, `Veille`, `Messages`, `Historique`, `Logs`) ; si `onglet`, cliquer le `[data-baseweb="tab"]` dont le texte égale `onglet` ; attendre la `cible` (premier sélecteur trouvé de la liste séparée par virgules ; 4 s max) ; puis `driver.highlight` / `drive(i)` avec l'élément ou au centre.
4. Boutons : « Précédent », « Suivant », « Terminer » à la dernière, et lien « Passer le tutoriel » ; progression « Étape n sur N » (`progressText`).
5. À la fin ou sur Passer : cliquer `.st-key-tutoriel_fini button` puis détruire le driver.
6. `animate` = `!matchMedia('(prefers-reduced-motion: reduce)').matches`.
7. Les étapes sont passées en JSON (`json.dumps(..., ensure_ascii=True)`) — l'échappement ASCII supprime tout `<` littéral.

  - `test_aucun_chevron_dans_le_script_inline` : pour chaque bloc `<script>` sans `src`, son texte ne matche pas `<[A-Za-z0-9]` (regex) — même avec un texte d'étape contenant `<b>`.

  - `test_le_fichier_statique_existe` : `static/driver.js.iife.js` existe et `config.toml` contient `enableStaticServing = true`.
